# PortioとCodexの接続

Portio 0.6.0以降には、このMac内で使うMCP接続が含まれます。新しい作業を始める際に、指定した個人用・大学用スペースで新タブを開き、そのタブを確認・操作します。既存タブを一覧取得・上書き・削除するツールはありません。

## 初回の設定

1. Portioを通常のアプリとして配置して起動します。配置場所を後から変えた場合は接続設定も更新してください。
2. サイドバーの「AI連携」を開き、「連携を有効にする」を選びます。アクセス範囲の説明を確認してください。
3. 「接続設定をコピー」で、このMacの配置場所に合った設定をコピーします。
4. Codexの設定→MCP serversでSTDIOサーバーを追加します。名前は `portio`、Commandはコピーした設定の `command`、Argumentsは `args` の各項目、Environment variablesは `ELECTRON_RUN_AS_NODE=1` です。設定ファイルを使う場合は、コピーした `[mcp_servers.portio]` のブロックをユーザー設定の `config.toml` に追加します。同名の設定は重複させないでください。
5. Portioの設定画面を閉じます。CodexのMCP設定で「Restart」を選ぶか、Codexを再起動して接続設定を読み込みます。その後、新しいチャットで利用してください。

例：「Portioで、https://example.com を開いて内容を確認して」。0.6.1以降は、依頼内容やプロジェクト設定から個人用・大学用が分かればAIがそのまま選び、判断できない場合や指示が食い違う場合だけ確認します。「大学用で」など、明示的な指定もできます。両方のログイン済みスペースを試したり、Gmail等の共通ドメインだけでアカウントを決めたりはしません。アプリ内に接続用の実行環境を含むため、利用者がNode.jsを追加インストールする必要はありません。

Codexへの登録は初回だけです。プロジェクトごとの手順追加は不要で、既存の「まずPortioを使う」という指示もそのまま使えます。MCP登録だけで他のブラウザより必ず優先されるわけではありません。Mac上のローカルSTDIOを利用できるCodex環境が対象で、Web版・クラウド実行からこのMacへ接続する仕組みではありません。

Codex側の設定項目は[公式MCP案内](https://learn.chatgpt.com/docs/extend/mcp.md)も参照してください。

## 作業と停止

- AIが依頼内容・プロジェクト設定からスペースを決め、最初の `portio_begin` にスペース・URLを渡して新しいタブを作ります。スペースの引数は必須です。アプリが省略時に推測して開くことはありません。
- `portio_read` で内容を確認し、直後の `portio_click`・`portio_fill`・`portio_select` にその確認結果を渡します。操作対象に関係する更新・30秒の経過・対象変更があれば取り直しを求めます。背景の保存表示等が更新されただけでは操作を止めません。操作後も `portio_read` で結果を確認します。
- 利用者が別のスペースやタブへ切り替えた場合、その作業への操作は止まります。対象タブを自分で選び直すと確認から再開できます。
- `portio_end` はアクセスだけを解除し、タブは開いたまま残します。
- Portioの「AI連携」で、すべての作業へのアクセス解除・連携停止ができます。Macのロックやスリープでも作業へのアクセスを解除します。

有効／停止の選択は再起動後も保持しますが、作業の識別子は保持しません。アプリや接続の再起動後は新しい作業から始めます。接続が強制終了され、作業枠が残った場合は「作業へのアクセスをすべて解除」で解除できます。同時に保持できる作業は8件です。

## 対応範囲と情報の扱い

通常のページ本文、ボタン、入力欄、標準の選択欄に対応します。対象は同じ通信方式・ホスト・ポートの最上位ページです。別サイトへの遷移・ログイン用の転送後は読み取りを止めます。必要な認証は利用者が行ってから、目的サイトで作業を開始してください。

埋め込み画面、shadow DOM、canvas、ファイルの送受信、一部の独自部品、人の実操作だけを受け付ける部品は対象外です。パスワード・確認コード・カード情報として識別できる入力欄と、パスワード欄を含むフォームは除外します。Cookie・保存済みパスワード・履歴を取り出すツールはありません。ただし、サイトが秘密を通常の本文や独自の入力欄に表示する場合まで完全に識別できる仕組みではありません。

MCPの読み取り結果（本文・通常の入力欄の値など）は接続したAIサービスへ渡ります。ページに表示された個人情報も含まれ得ます。Portio自身はページ内容の操作ログを保存しません。AI側の記録・承認・送信前確認は、そのサービスと利用者の指示に従います。MCPは承認審査やサイトの認証制限を迂回する機能ではありません。

Mac内の私有ソケットと接続用の鍵を使い、Web向けの待ち受けポートは開きません。同じMacアカウントで動く悪意あるソフトから情報を隠す境界ではありません。信頼するMCPクライアントだけに登録してください。[データの扱いと点検の限界](AI-DATA-REVIEW.md)も参照してください。

## 動作確認

[TESTING.md](../TESTING.md)に、公式MCPクライアントと架空ページを使った確認内容を記載しています。この接続はOSのウィンドウ認識を使わず作業用タブを指定しますが、以前の画面取得側の不一致の根本原因を解消したと判断するものではありません。

## 操作できないとき

`OBSCURED`は、操作対象に届く位置を確認できない場合に表示します。0.6.3では、課題行などの中央に別の表示部品が重なる場合、画面内の複数の位置を確認するよう修正しました。対象が完全に覆われている場合は引き続き停止します。確認画面やメニューを閉じてから読み取り直してください。

`STALE_SNAPSHOT`は、使用済みの操作情報、URL変更、30秒の期限切れ、操作対象に関係する変更を区別して案内します。直前に`portio_read`で取り直し、その結果の要素を使ってください。0.6.2では背景の保存表示等だけで全要素を無効にしていた判定を修正しました。対象自体が更新され続ける場合に、無条件でクリックを通したり、自動でクリックを繰り返したりはしません。

`noWindowsAvailable`はMCPのページ操作とは別の、Macの画面操作経由で報告されたエラーです。ページの読み取り成功だけで画面クリックも可能とは判断しません。再発時は再起動前に、許可された範囲の時刻・版・操作情報・画像・OSのウィンドウ情報をローカルへ記録してください。操作対象を確認できなければ停止し、古い座標や要素番号を使って続けないでください。
